# Vault HQ 2.0 — specification

The contract every workstream builds against. If code and this file disagree, this file
wins until it is changed on purpose, in its own commit, with every affected stream told.

## 1. What 2.0 is

One self-contained macOS app that is the whole interface to a local "second brain": a
folder of well-structured markdown that the user, their editors and their AI agents all
write into. No Obsidian, no Node server, no background LaunchAgent, no Taskwarrior.

**Principles**
- **Local only.** Nothing leaves the Mac except: requests to a model server the user
  chose (loopback or home network only), fetching a page the user saved as a bookmark
  (title/summary, on their action), and a JSON status widget URL the user configured.
  No accounts, no telemetry, no sync service. Multi-Mac = put the vault in a folder the
  user already syncs (iCloud Drive, Dropbox, a shared drive).
- **Markdown is the source of truth.** Every note, task and bookmark is a plain `.md`
  file an agent can read with `cat`. Anything the app keeps elsewhere (search vectors,
  task index, settings, conversations' UI state) is a cache or a preference and can be
  rebuilt or lost without losing knowledge.
- **No plugins, no logins.** Agents connect through the built-in MCP server or by plain
  file conventions. Browsers are read from their own bookmark files, per browser, only
  after the user says yes.
- **One process.** The Tauri app *is* the backend: Rust core in-process, React UI over
  Tauri commands. The only other process is the same binary started as `vault-hq mcp` by
  an agent (stdio MCP server), which uses the same core and the same file locks.
- **Safe writes.** Every write to an existing file goes through `hq_core::locks`:
  `flock` on the file, compare SHA-256 with what the writer read, write in place (never
  rename-over: another writer may hold the lock on that inode).

**Non-goals for 2.0:** voice capture (phase 2), a browser extension (never), sync,
mobile, Windows/Linux builds, the Mac App Store.

## 3. The vault format, v1

A vault is a folder. HQ marks it with `.vault-hq/vault.json`:
```json
{ "format": 1, "id": "b3f1c2…", "name": "home", "created": "2026-11-02" }
```
`id` is a random 128-bit hex string, stable for the vault's life (survives moves).

**Folders** (created by onboarding; HQ reads any vault, these are defaults):
```
00-Inbox/        captures, agent session notes, proposals (nothing filed without a human look)
01-Projects/     one note per project
02-Areas/        ongoing responsibilities (no end date)
03-Learning/
04-Personal/
05-References/   reference notes; *-findings.md are findings logs
06-Memory/       facts agents should remember about the user
07-Agents/       one note per agent: what it may do here
08-Archive/
09-Planning/     Daily/YYYY-MM-DD.md, Weekly/, decision-log.md, Tasks.md (loose tasks)
10-Bookmarks/    <source>/<slug>.md, one note per bookmark
_templates/      note templates (not listed as notes)
AGENTS.md        the agent contract for this vault (onboarding writes it)
```
Skipped when scanning: names starting with `.`, `_tools/`, `_templates/` (listed only
by template pickers), `node_modules/`.

**Frontmatter** (between `---` lines at the very top; `key: value`, one per line;
values are strings; lists as `[a, b]`):

| key | required | meaning |
|---|---|---|
| title | yes | display title (falls back to file stem) |
| type | yes | note, project, area, reference, findings, daily, capture, session, proposal, bookmark, memory, agent, index |
| created, updated | yes | `YYYY-MM-DD` |
| author | yes | `human`, or the agent's name (`claude`, `cursor`, `codex`, `hq`) |
| tags | no | `[a, b]` |
| status | projects | active, paused, done, archived |
| url, source, added, platform | bookmarks | see section 8 |

Every HQ write bumps `updated:` to today when the note has frontmatter.

**Daily notes** `09-Planning/Daily/YYYY-MM-DD.md`: `## Quick Wins`, `## Work`,
`## Learning`, `## Tomorrow` (human), `## Agent log` (agents append `- HH:MM who · text`).
Underscored frontmatter keys (`tasks_pending: 12`) are daily metrics.

**Links:** `[[stem]]`, `[[stem|alias]]`, `[[stem#heading]]`, `![[embed]]`, and relative
markdown links. Resolution: exact vault-relative path → path + `.md` → case-insensitive
path → path suffix → stem. Resolution never leaves the vault.

**Identity across vaults:** a note's id is `NoteId { vault: VaultId, rel: String }`,
serialized as `"<vaultId>:<rel>"`. The UI and MCP always use this form.

## 4. Tasks

### 4.1 Storage — a checkbox line, Obsidian Tasks compatible
```
- [ ] Lay the main line along the fence #garden #outdoor ⏫ ➕ 2026-10-20 🛫 2026-10-28 ⏳ 2026-10-30 📅 2026-11-01 🔁 every week 🆔 a1b2c3 ⛔ x9y8z7
    - Annotation: parts are in the garage (2026-10-29)
```
| field | syntax | Taskwarrior equivalent |
|---|---|---|
| status | `[ ]` pending, `[/]` started, `[x]` done, `[-]` cancelled, `[>]` waiting | status / start |
| priority | 🔺 highest, ⏫ high, 🔼 medium, 🔽 low, ⏬ lowest | priority H/M/L |
| tags | `#tag`, `#a/b` nested | tags |
| project | the containing note if `type: project`, else `#project/<name>` | project |
| created | `➕ date` (HQ adds it on create/first edit) | entry |
| start | `🛫 date` | start |
| scheduled | `⏳ date` | scheduled |
| due | `📅 date` | due |
| done / cancelled | `✅ date` / `❌ date` | end |
| recurrence | `🔁 every day|week|month|year|N days|weekday` | recur |
| id / depends | `🆔 id` (6 chars `[a-z0-9]`), `⛔ id,id` | uuid / depends |
| wait | `[>]` plus `⏳ date` = hidden until then | wait |
| annotations | indented `- ` lines directly under the task | annotate |

Every open task HQ touches gets a `🆔`. Ids are unique per vault.

### 4.2 Engine (`hq_core::tasks`)
- Parse every in-scope note (excluded: `08-Archive/`, `_templates/`, `00-Inbox/` session
  and compact notes) into `Task` (section 10). The index is in memory, rebuilt from the
  watcher's changes; a cache file (`tasks-index.json` in the app's cache dir) speeds startup.
- **Query**: filter by status, project, tags (all/any/none), priority, due/scheduled
  ranges, text, vault; sort by urgency/due/priority/created/project; group by project,
  tag, due bucket (overdue, today, this week, later, none), priority, vault, note.
- **Urgency** (Taskwarrior's defaults, so it feels familiar): due (12.0 scaled by
  proximity, overdue = full), priority H 6.0 / M 3.9 / L 1.8, started 4.0, blocking 8.0,
  blocked −5.0, scheduled 5.0 when past, age 2.0 (over a year), tags 1.0 per tag up to 3,
  project 1.0, waiting −3.0, annotations 1.0.
- **Mutations**: add (to a project note's `## Tasks` section, or `09-Planning/Tasks.md`),
  update fields, start/stop, done (recurring: insert the next occurrence above), cancel,
  delete (removes the line), annotate, move between notes. All go through
  `locks::guarded_edit` on the containing note, keyed by `🆔`, never by line number.
- **Stats**: per day created/done/cancelled; open count over time; burn-down for a
  project or tag; completion rate (7/30 days); by project/tag/priority; overdue trend.
  Derived only from `➕`, `✅`, `❌` dates and the current state.
- **Import from Taskwarrior** (`import_tw.rs`): read `task export` JSON (only if the
  `task` binary exists and the user asks); map fields per the table; write into the
  project note named after `project` (create it if missing) or `09-Planning/Tasks.md`;
  dry run first, showing counts and a sample; never deletes Taskwarrior data.

## 5. Notes, capture, create

- List, read (frontmatter, body, links, backlinks), create, save (guarded; conflict
  returns the current text + hash), rename/move (updates `[[links]]` that point to it,
  after confirmation, all guarded), archive (move to `08-Archive/`).
- **Create**: a note from a template (`_templates/*.md`, `{{title}}`, `{{date}}`), a task
  (section 4), a bookmark from a pasted URL (section 8), a quick capture.
- **Quick capture** (menu-bar popover and global hotkey ⌥⌘Space): one text box; Enter
  appends `- HH:MM text` to `00-Inbox/YYYY-MM-DD-capture.md` (creates it with
  frontmatter); `⌘Enter` makes it a task; a URL alone becomes a bookmark.

## 6. Search and Ask

- Chunks: heading-sized sections, max ~1,200 chars, with note dates (created, updated,
  filename) for day scoping. Index: BM25 in memory + embeddings from the user's embedding
  model, persisted in the cache dir keyed by (vault id, rel, chunk hash, model). Changing
  the embedding model drops the vectors.
- Ranking: `weight(folder) × (0.45 × bm25_norm + 0.55 × cosine)`; projects 1.2,
  references 1.1, bookmarks 1.0, sessions/inbox 0.85.
- **Ask streams**: `ask_start` returns a request id at once; tokens arrive as `ask://event`
  events (`{id, kind: "sources"|"token"|"done"|"error", …}`); `ask_cancel(id)`.
- **Conversations**: the Ask tab is a chat. Each conversation is saved as a note in
  `06-Memory/conversations/YYYY-MM-DD-<slug>.md` (`type: conversation`, `author: human`),
  so it is searchable knowledge, not app state. Follow-ups send the last N turns.
- Scope: all vaults or chosen ones; all time or a window of days; notes, bookmarks or both.

## 7. Local AI (Ollama)

- Detect: `GET {url}/api/tags` (default `http://127.0.0.1:11434`); also report whether the
  `ollama` binary exists (`/opt/homebrew/bin/ollama`, `/usr/local/bin/ollama`,
  `/Applications/Ollama.app`).
- Allowed server addresses: http, host = loopback, RFC 1918, link-local, or `*.local`.
- **Recommendations** by unified memory (`sysctl hw.memsize`): embeddings
  `nomic-embed-text` (always); chat ≤ 8 GB `llama3.2:3b`, 16 GB `qwen2.5:7b` or
  `llama3.1:8b`, 32 GB `qwen2.5:14b`, ≥ 64 GB `qwen2.5:32b`. Show the `ollama pull …`
  commands; offer a "copy" button; never run installs silently.
- Bookmark enrichment (tags + one-line summary) uses the chat model, opt-in, batched,
  cancellable.

## 8. Bookmarks

- **Sources** (detection lists only what exists, with item counts once allowed):
  Chromium family JSON `Bookmarks` under `~/Library/Application Support/<vendor>/<Profile>/`
  for Chrome, Brave, Edge, Arc (`Arc/User Data`), Dia, Vivaldi, Chromium; Firefox
  `places.sqlite` (copied to a temp file first; it is locked while Firefox runs); Safari
  `~/Library/Safari/Bookmarks.plist` (needs Full Disk Access: HQ explains how, and offers
  importing a Safari "Export Bookmarks" HTML file instead); any Netscape bookmarks HTML file.
- **Permission**: nothing is read until the user ticks that browser/profile in onboarding
  or Settings. The choice is remembered per browser profile; re-scans run only for
  allowed ones (hourly, in `jobs.rs`).
- **Storage**: one note per URL in `10-Bookmarks/<source>/<slug>.md`:
  ```
  ---
  title: …            type: bookmark     url: https://…
  source: chrome      folder: Bookmarks Bar/Reading   platform: youtube
  added: 2026-03-04   created: …  updated: …  author: hq   tags: [ … ]
  ---
  <summary, if enriched>
  ## Notes
  ```
  Dedupe by normalized URL (lowercase host, no fragment, no utm_*). A re-scan adds new
  ones and never deletes (a bookmark removed in the browser stays, with `status: removed-in-browser`).
- **Paste a link**: creates the note at once (title = URL); fetching the page title and
  description happens in the background, only for that URL.
- **From Daymark**: daily memory on Home (1–2 items older than 7 days, not shown in the
  last 14, prefer ones with notes/tags/summary, stable per day via a seeded shuffle,
  "show different ones" re-salts, dismiss hides for good; state in settings);
  platform badges (YouTube, GitHub, X, Reddit, Hacker News, Instagram, TikTok, article, PDF).

## 9. Agents and MCP

- `vault-hq mcp` speaks MCP over stdio (JSON-RPC 2.0, protocol revision 2025-06-18).
- **Tools**: `search(query, scope?)`, `ask(question, scope?)` (non-streaming),
  `read_note(id|ref)`, `list_notes(folder?, type?, updated_since?)`, `create_note(...)`,
  `append_to_note(id, heading?, text, base_hash)`, `capture(text)`,
  `add_task(...)`, `update_task(id, patch)`, `list_tasks(query)`, `add_bookmark(url, note?)`,
  `log(text)` (agent log line in today's daily note), `vault_info()`.
- **Resources**: `vault://AGENTS.md`, `vault://note/{id}`.
- Writes from MCP set `author` to the client's name (from `initialize.clientInfo.name`)
  and are guarded exactly like UI writes. Deletion is not exposed over MCP.
- **Onboarding writes agent configs** only after a per-agent confirmation, showing the
  exact file and diff: Claude Code (`claude mcp add vault-hq -- <bin> mcp` printed as a
  command), Claude Desktop (`~/Library/Application Support/Claude/claude_desktop_config.json`),
  Cursor (`~/.cursor/mcp.json`), Codex (`~/.codex/config.toml`). For each it also shows a
  copy-paste **prompt/skill** text (section 11 of onboarding) and, for tools without MCP,
  file-convention instructions (where to write, frontmatter, never delete).

## 11. Onboarding (first run; re-runnable from Settings)

1. **Welcome** — what HQ is, local-only promise.
2. **Your brain** — create a new vault (pick a folder; iCloud Drive suggested for multiple
   Macs) or add existing ones; several vaults allowed (home, team, …); one is primary
   (captures go there). Import from Obsidian: analyze (notes without frontmatter, loose
   files at the root, unknown folders, broken links, untagged notes), show a plan, apply
   only what the user ticks; tag suggestions from the local model if available.
3. **Your agents** — tick Claude Code, Claude Desktop, Cursor, Codex, ChatGPT, others; per
   agent: connect via MCP (preview + confirm) and/or copy its prompt/skill text.
4. **Tasks** — start fresh, or import from Taskwarrior (dry run, then apply).
5. **Local AI** — detect Ollama; pick embedding + chat models from installed ones, or show
   recommended pulls; skip allowed (Ask is then search-only).
6. **Bookmarks** — detected browsers with a checkbox each; Safari explains Full Disk
   Access or HTML export; import with progress; optional enrichment.
7. **Done** — land on Home.

State lives in settings (`onboarding.step`, `onboarding.done`). Each step can be skipped.

## 12. Widgets

A Home row of user-arranged widgets (drag to order, add/remove, per-widget settings):
`system` (CPU, memory pressure, disk free, battery, uptime; sampled every 5 s by
`jobs.rs` with `sysinfo`), `tasks_burn` (open over 30 days, done per day),
`tasks_due` (due soon), `focus` (top urgency), `inbox`, `memories` (Daymark),
`json_status` (any URL returning JSON; user maps fields → label/value/ok; polled at the
user's interval, minimum 60 s), `clock`. Layout and configs in settings.

## 13. Settings, files, privacy

- App files: `~/Library/Application Support/local.vaulthq.desktop/` (settings.json,
  conversations UI state), cache `~/Library/Caches/local.vaulthq.desktop/` (vectors, task
  index). Never inside a vault except `.vault-hq/vault.json` and notes.
- `Settings`: vaults[], primaryVault, blockedVaultNames[], ollama{url, chatModel,
  embedModel}, theme, hotkeys{palette, capture}, browsers{allowed per source},
  bookmarks{enrich}, widgets{layout}, memories{dismissed, lastSurfaced}, onboarding{…}.
- `blockedVaultNames`: a vault whose folder name matches is refused before anything inside
  it is read (this Mac sets `work-vault`, `art-vault`).
- Tauri: capabilities allow only HQ's own commands and events; CSP `default-src 'self'`
  plus Google Fonts; external links open in the default browser.

## 14. CI and checks (`.github/workflows/ci.yml`, macOS arm64)

Every push to `v2`/`main` and every PR runs, and must pass:
1. `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`
2. `cargo test --workspace` (unit + integration on `tests/fixtures/demo-vault`)
3. ts-rs bindings up to date (regenerate, `git diff --exit-code web/src/bindings`)
4. `npm ci`, `npm run typecheck`, `npm run test` (vitest), `npm run build`
5. `cargo deny check` — licenses allow MIT/Apache-2.0/BSD/ISC/Zlib/Unicode/MPL-2.0;
   **deny GPL/AGPL/LGPL** (keeps the MIT promise and Daykeep's AGPL code out); advisories
6. `npm audit --omit=dev --audit-level=high`
7. `tauri build --no-bundle` (the app compiles)
8. privacy scan: no `/Users/<name>`, private IPs, or terms from `.privacy-terms` (kept
   only on the maintainer's Mac and passed in locally; CI uses the generic patterns)

**Releases are signed only on the maintainer's Mac** (`scripts/release.sh`): build,
codesign with the Developer ID Application identity (hardened runtime), `xcrun notarytool
submit --keychain-profile vault-hq --wait`, `xcrun stapler staple`, DMG, then a GitHub
Release with the DMG and its SHA-256, then a Homebrew tap bump
(`Athreyas/homebrew-tap`, `Casks/vault-hq.rb`). No signing secrets in CI.

## 15. Workstreams (phase 1)

Each stream works in its own git worktree and branch (`v2-<stream>`), touches only the
files it owns, adds tests, keeps CI green, and ends with a PR into `v2`.

| stream | owns |
|---|---|
| A core | `vault/`, `notes.rs`, `capture.rs`, `days.rs`, `home.rs`, `needs.rs`, `inbox.rs`, their commands |
| B tasks | `tasks/`, its commands, `web/src/components/Tasks*` (list, groups, filters, stats/burn-down) |
| C search | `search/`, `ollama.rs`, their commands, `web/src/components/Ask*` (chat, streaming, history) |
| D shell | `web/src/api.ts`, `App.tsx`, Home/Days/Needs/Inbox/Notes/Editor/Palette/Settings views, create flows, quick-capture window, tray + hotkeys in `src-tauri` |
| E onboarding | `onboarding/`, its commands, `web/src/components/onboarding/*` |
| F bookmarks | `bookmarks/`, its commands, `web/src/components/Bookmarks*`, memories widget |
| G mcp | `crates/hq-mcp/`, `vault-hq mcp` entry |
| W widgets | `widgets/`, its commands, `web/src/components/widgets/*` |
| H release | `.github/`, `deny.toml`, `scripts/release.sh`, Homebrew cask, README install section |

Shared files (`types.rs`, `lib.rs` module list, `src-tauri/src/main.rs` command
registration, `web/src/App.tsx` routes) change only by adding lines in the marked
sections; merge conflicts there are resolved by the integrator.
